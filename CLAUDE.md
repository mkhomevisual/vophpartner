# CLAUDE.md – VOPH Partners Website

## Project identity

You are working on a one-page website for VOPH Partners.

VOPH Partners is a modern FMCG trading and sourcing partner. It helps wholesalers, retail chains, large e-shops, distributors and major market players obtain leading global-brand products at competitive prices.

The site must communicate trust, speed, international sourcing capability, logistics competence and long-term partnership.

## Source of truth

Read `references/voph-project-brief.md` before making product, content or visual decisions.

If there is a conflict between generated ideas and the brief, the brief wins.

## Website goal

The website should generate B2B enquiries and make it easy for a professional visitor to:

- schedule a meeting,
- contact the company,
- understand the services quickly,
- trust the company as a serious FMCG trading partner.

## Required page structure

Build a one-page landing page with these sections:

1. Navigation.
2. Hero.
3. About.
4. Services.
5. Why VOPH Partners.
6. Brand / product cooperation strip.
7. Process or partnership model.
8. Visual / logistics credibility section.
9. Contact CTA.
10. Footer.

## Tone of voice

Use short, confident B2B copy.

The tone is:

- modern,
- practical,
- minimalist,
- reliable,
- confident,
- international,
- direct,
- long-term oriented.

Do not write like a retail e-shop.
Do not write like a generic logistics company.
Do not overexplain.

## Visual direction

Use a premium dark interface with light elements, strong spacing, large typography, subtle borders, restrained accents and minimal motion.

The design should feel like a 2026 trading company, not an old FMCG distributor.

Avoid:

- cheap stock photography,
- AI-generated people,
- handshake photos,
- fake corporate team photos,
- loud colors,
- generic WordPress template layout,
- overfilled sections,
- excessive text.

## Frontend standards

When editing frontend code:

- Inspect the existing stack before making changes.
- Keep components small and readable.
- Prefer semantic HTML.
- Maintain responsive layout from 360px to large desktop.
- Preserve accessibility: contrast, focus states, keyboard navigation, alt text, labels.
- Avoid adding heavy dependencies unless clearly justified.
- Do not break existing build scripts.
- Run lint, typecheck and build commands when available.

## CSS / UI standards

Prefer:

- design tokens,
- consistent spacing scale,
- reusable section components,
- clear typographic hierarchy,
- dark surfaces,
- subtle gradients,
- thin dividers,
- grid-based layouts,
- clean cards,
- elegant hover states.

Avoid:

- random one-off values,
- overly decorative shadows,
- excessive animations,
- fake 3D,
- low-contrast text,
- generic SaaS blue template feel.

## Motion standards

Use motion only to improve perceived quality.

Good motion:

- subtle reveal on scroll,
- slow gradient shift,
- soft card hover,
- restrained CTA hover,
- logistics line/path animation.

Bad motion:

- bouncing elements,
- noisy parallax,
- aggressive transitions,
- animation that distracts from B2B credibility.

## Content rules

Do not invent specific phone numbers, email addresses, legal details, certifications, warehouse locations or brand permissions.

Use placeholders where data is missing:

- `[PHONE]`
- `[EMAIL]`
- `[MEETING_LINK]`
- `[ADDRESS]`

## Review checklist

Before finishing, check:

- Does it look premium and B2B?
- Is it clearly not a retail e-shop?
- Is the hero immediately understandable?
- Are CTAs visible?
- Is the copy short?
- Does it avoid clichés?
- Does it work on mobile?
- Does it pass basic accessibility?
- Does the build pass?
